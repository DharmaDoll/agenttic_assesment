# 自律型エージェントによる継続的な脆弱性検知

このリポジトリは、自社の脆弱性をAIエージェントを使う攻撃者より早く検知するためのPoCと、その後の継続運用を計画する文書をまとめています。最初は対象を限定して実際にagentを動かし、探索した範囲、確認済みの問題、未確認箇所、所要時間と費用を記録します。

現時点の成果は計画書とA案の仕様書です。アプリケーションコード、テスト、診断の実行結果、日次スケジューラはまだありません。各文書中のコマンド候補、工数、数値目標は実装・検証前の案です。

## 文書の読み方

| 文書 | 役割 |
|---|---|
| [導入提案](agentic-security-plan.md) | 目的、対象範囲、開始権限、A〜D案の位置付け、評価・採用基準を定める。共通方針の正本 |
| [A案：Strix実行計画](strix-continuous-assessment-plan.md) | 最初に試す構成。手動PoCのP0〜P4から、反復・日次運用・採用判断までの工程 |
| [A案：Strix仕様書](strix-continuous-assessment-spec.md) | A案で満たす動作、入力・出力、異常時の扱い、初回PoCの受け入れ条件。実装・検証時の参照先 |
| [B案：Cairn実行計画](cairn-continuous-assessment-plan.md) | 状態を持つ業務フローや複数段階の探索で追加価値を測る工程 |
| [C案：Hermes＋Strix実行計画](hermes-continuous-assessment-plan.md) | Hermesによる次の探索の選択・要約・知識の引継ぎが検知と人手に与える効果を測る工程 |
| [D案：ARTEX実行計画](artex-continuous-assessment-plan.md) | 統合UI・探索状態・証拠管理の利点と、ビルド・DB・運用負荷を測る工程 |

| [対象技術台帳](TARGET_TECH_STACK.md) | 対象技術の105項目。導入済み依存や検査済み項目の一覧ではない |

最初に導入提案で目的と範囲を確認し、A案の実行計画と仕様書から初回PoCの条件を読む構成です。B〜Dは比較候補として計画を用意しています。Aを先に試す判断と、その時点での未確認事項は構成判断記録にあります。各案の性能や継続運用への採用は、まだ実測していません。

## 最初のPoCで確認すること

対象・許可操作・モデル・入力資料・予算を決め、固定したツールを限定環境で起動します。agentの探索結果と原証拠を保存し、脆弱性領域ごとに「確認した内容」「該当しない根拠」「未確認の理由と次の検査」を残します。候補は人が独立して再現し、起動成功、検査範囲、検出の有効性を別々に判定します。

日次の自動化、反復比較、修正後の再検証は手動PoCの結果を見て進めます。モデルや資料の組合せを網羅的に比べることより、まず代表的な構成が対象に対してどのような結果を出すかを確認します。実際の対象、資格情報、版、予算、保存先は各案のP0〜P2で確定します。

実装を始める際は[リポジトリ指針](AGENTS.md)に従い、最初のコードとともに実際のセットアップ・実行・テストコマンドをここへ追記します。
